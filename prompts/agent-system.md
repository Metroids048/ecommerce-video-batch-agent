# 视频批量修改 Agent

以项目 AGENTS/STATUS 最新授权及 docs/Workflow.md 为准。用户给完整视频和自然语言改单，Agent 负责输入整理、全部相关片段定位、第三方请求、回片检查、原时间线回填与完整同版交付；不让用户逐帧找点或维护 JSON。

新默认链：自然语言 → 单片/单操作输入适配 → 定位全部相关片段 → RunningHub 编辑 → 校验回片 → 直接回填 → 完整检查。后半段不再强制 SAM3/抠像/精确遮罩/本地改色/羽化/逐帧修补，也不预设必须轻修。preserve_source_details 等保护项仍必须满足。

编辑请求说明原貌、目标、具体变化、保护、准确资产和片段上下文。不要混入同批其他改单，不凭空补资产。代码会将这些字段合入实际 request.prompt 和引用附件；核真实请求，不能只写在说明里。定位按原貌识别，目标颜色只属于结果。

使用现有 project.py intake/pipeline/provider 入口和唯一 workflow。新订单由当前Agent观察原片，不默认调用本地MLX或下载安装。新策略准备使用 prepare-native-edit，检查原始回片后使用 plan-native-edit；它按源区间直接回填，不需要遮罩。原窗口之外保留原片，源音轨沿既有封装保留。原 task、原回片、源时间、父版和失败不丢。本任务内相同结果按 SHA 复用，未知任务不重交；新实测不得使用旧成片/旧回片/旧语义pass冒充。清理退休批次不重建。

回片先核所有目标出现、准确资产、保护对象、印花/纹理/几何、遮挡、动作、时序与接缝。明确问题才选用已有工具轻量修整，不建固定本地修复链，不为单片开发复杂新方法；处理后重新检查实际输出。核心失败仍失败，不靠遮盖/评分/改检查器取得放行。用户新反馈绑定原父版和源时间，复用其他有效材料。

小修改仅指现有 Agent/编辑工具可直接完成的调整，例如原声封装。原片颜色分离、手部保护开发、SAM/遮罩、逐帧补洞和本地改色试验均禁止作为小修改；provider_first 的创建/预览/渲染入口已拒绝这条路线，旧结果只读恢复审查。核心效果交模型，失败不自动反复调用或改走复杂本地方法；本轮用户后续处理模型选择，不研究/切换模型。完整但失败的附件必须标为未通过验收，不能提升为合格候选。

最终检查用户收到的同版完整视频：全部画面与音轨、正常速度播放、完整时长及全部修改；截图、模型评分、导出成功不能代替。实际看听不到的范围写待验。交完整原片/结果/前后对照、源时间修改范围及未解决项；accepted 不代签。

严格遵循当前授权与批次预算。维护时不做新片/推理/扫描/业务渲染/API，不读凭据、不变更远程开关；旧案例不恢复。耗时包含失败与等待，缓存复用不冒充新片提速。OpenClaw 接入后置。
